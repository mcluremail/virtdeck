# План аудита UX/UI VirtDeck (серия UX, этапы UX-0…UX-8)

Дата: 2026-10-16. Статус: план утверждён владельцем; выполнение поэтапное
(после каждого этапа — свод находок владельцу, следующий этап по команде).

## 1. Принципы и преемственность

- Числовые серии 6.x (и возможные 7.x) — аудиты ChatGPT; к ним возможно
  возвращение, нумерацию не занимаем. Наша серия этапов — **UX-\***.
- Дефекты: серия **A** (aesthetics — визуальный язык) и **U** (usability —
  интеракция/состояния/тексты). С D-серией не пересекаются.
- Сквозной принцип прошлых аудитов — честность данных; переносим на интерфейс:
  **UI не врёт** ни состоянием (успех там, где неизвестно), ни внешним видом
  (аффордансы не лгут, визуальный язык не противоречит структуре).
- Методика — развитие `docs/AUDIT_PROCESS.md`: это «полный» аудит (все
  поверхности, не дельта) с той же дисциплиной доказательности: каждый дефект —
  file:line, severity, вред для оператора, предложение фикса; 🔴/🟡/✅ в отчёте.

## 2. Правила доказательности для эстетики

1. Ключевой метод — **отрисовка**: `QT_QPA_PLATFORM=offscreen`, инстанциация
   поверхности на тестовой сцене (как в tests/ui), `widget.grab()` → PNG,
   **визуальный разбор картинки**. Статику оцениваем по изображениям; динамику
   (hover/анимации) — по коду + точечным захватам состояний.
2. Каждый A-вывод обязан иметь: (а) нарушенный пункт рубрики (§3), (б) картинку
   + `file:line` порождающего кода, (в) вред для оператора (риск ошибки, цена
   сканирования), (г) конкретный фикс. Формулировок вида «сделать красивее» нет.
3. Обязательная маркировка: «нарушение внутренней согласованности»
   (объективно, 🔴/🟡) отдельно от «вкусового наблюдения» (только 🟡).
4. Эталон — собственный визуальный язык приложения и конвенции операторских
   инструментов (Proxmox VE, virt-manager), **не** «закос под Apple».

## 3. Рубрика эстетики (эталон, фиксируется до поиска дефектов)

1. **Иерархия и приоритет взгляда**: за один фикс-взгляд — статус → объект →
   действие; уровни различимы размером/весом, а не только цветом.
2. **Единый визуальный язык**: одна шкала отступов, одна типографическая шкала
   (посчитать фактическое число кеглей/весов), сетка выравнивания; близкое
   сгруппировано, далёкое разведено (закон близости).
3. **Цвет = смысл**: DANGER/WARN/OK несут только семантику; декоративного цвета
   нет; одна семантика выглядит одинаково на всех поверхностях и во всех темах.
4. **Правда аффордансов**: кликабельное выглядит кликабельным, disabled
   очевиден, hover/pressed читаются; «мёртвых» декораций под контролы нет.
5. **Плотность операторского инструмента**: информационно насыщенно, но
   сгруппировано; без маркетинговой воздушности и без свалки.
6. **Типографика данных**: VMID/IP/даты — mono; интерфейсные тексты — UI-шрифт;
   усечение длинных имён предсказуемо и единообразно.
7. **Ритм и полировка**: согласованные радиусы, бордюры, паддинги; стыки
   поверхностей без «шероховатостей».

Иконки исключены из рубрики и объёма (отдельная будущая тема: `icons.py`,
набор SVG, метафоры, направленность в RTL).

## 4. Этапы

### UX-0. Картография (инвентаризация)
- Реестр поверхностей: `mainwindow.py` (меню/тулбар/док-панели), `tree_panel`,
  `detail_panel/`, `pbs_panel`, `fleet_health`, `search_dialog`,
  `command_palette`, `notification`, `about_dialog`, все диалоги `ui/*_dialog.py`,
  `console/`, `api/`.
- Программная инстанциация каждой поверхности offscreen (тестовая сцена из
  tests/ui) — попутная проверка «создаётся ли без живого PVE».
- Таблица: поверхность | модуль | точки входа | достижимые состояния | темы.
- Черновик матрицы «действие × точка входа» (полная — в UX-4).
- Фиксация рубрики §3 в отчёте как эталона.

### UX-1. Дизайн-система и тема-движок (уровень кода)
- Чтение: `theme.py` (контракт ThemePlugin v1), `docs/THEMES.md`, `brand.py`,
  `hover.py`, `optimistic.py`. Без `icons.py`.
- Поиск нарушений контракта: `rg "setStyleSheet"`, hex-литералы цветов,
  пиксельные константы отступов мимо токенов, прямые `QFont`/`setPointSize`,
  рассинхрон семантики `Color` между поверхностями.
- Выход: матрица «файл UI × использование токенов vs хардкод».

### UX-2. Отрисованная эстетика (ядро аудита)
- Рендер-матрица: поверхности (из UX-0) × 5 тем × ключевые состояния
  (дефолт, пустая БД, ошибка провайдера, частичные данные — заглушки тестовой
  сцены).
- Разбор каждой картинки по рубрике §3; межтемное сравнение одной поверхности
  (ловит «в тёмной теме рваное»).
- A-дефекты: id, путь к PNG-доказательству, file:line, пункт рубрики, вред,
  фикс, severity.

### UX-3. Честность состояний и обратная связь
- Каждая вьюха: пустое/загрузка/ошибка/частичные данные/неизвестно — есть ли
  явное состояние; молчаливое отсутствие не должно читаться как «всё хорошо»
  (наследие D4).
- Преемственность паттернов 6.3.x: «PBS freshness unverified», «Runway data
  unavailable», «outcome unknown», метка обрезанной истории задач.
- `optimistic.py` / `notification.py`: логика оптимистичных действий, дубли
  уведомлений, согласованность disabled-логики.

### UX-4. Матрица соответствия действий (обязательный этап)
- Источник: `action_registry.py` / `action_specs.py`.
- Матрица «действие × точка входа»: главное меню, тулбар, контекстные меню
  дерева и detail-панели, кнопки поверхностей, command palette, шорткаты.
- Ищем: действие доступно в одной точке и отсутствует в другой; разные ярлыки
  (tr-ключи) одного действия; расхождение confirm-логики у деструктивных;
  расхождение enabled/disabled-условий; действия, реализованные мимо реестра.

### UX-5. Интеракция и потоки
- Диалоги: порядок и дефолтные кнопки, Escape/Reject, блокировка двойного
  сабмита, политика фокуса.
- Деструктивные действия: единый паттерн подтверждения во всех точках входа
  (стык с UX-4).
- Навигация: `reveal_key` / `find_item_by_key`, B20-ключи (2- и 4-элементные).

### UX-6. Тексты, i18n, RTL
- Терминологическая таблица по tr-ключам: storage/datastore, task/job,
  host/node и пр.; расхождения формулировок одного понятия.
- Рендеры ключевых поверхностей в 6 локалях; усечения длинных строк;
  множественные формы.
- Арабский: `setLayoutDirection(RightToLeft)` — зеркалирование раскладки;
  LTR-токены (IP, VMID) внутри RTL-строк. Направленные иконки — в иконную тему.

### UX-7. Доступность и эргономика
- Keyboard-only проход: tab-цепочки, шорткаты, конфликты мнемоник.
- Доступные имена у иконочных кнопок (наличие `AccessibleName/Description`,
  не дизайн самих иконок).
- Цели нажатия, минимальные кегли, HiDPI (рендер при DPR 1 и 2).
- Дальтонизм-безопасность: danger/warn различимы не только оттенком (текст,
  форма, позиция).

### UX-8. Консолидация
- Свод A/U-дефектов по severity; итоги матриц UX-0/UX-4.
- Отчёт `docs/AUDIT_<дата>_UX_UI.md` (scope таблицей, 🔴/🟡/✅).
- План фиксов по приоритету вреда оператору; фиксы — после утверждения
  владельцем, test-first, эстетические — с рендером «до/после».

## 5. Границы

- **Иконки** — вне объёма (отдельная тема).
- **Сайт** virtdeck.mclure.ru — отдельный просмотр, не в этом аудите.
- Айдентика (`brand.py`, логотипы) не трогается; редизайн «под Apple» не
  проводится.
- Контракты воркеров/API (домен 6.3.x) не изменяются.

## 6. Протокол выполнения

1. Поэтапно: UX-0 → свод находок владельцу → команда → UX-1 → …
2. Гейты на каждое изменение кода: `ruff check virtdeck/ tests/` +
   `QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q -n 3` +
   `scripts/check_release.py`; i18n-паритет ключей.
3. Фиксы — только после UX-8 и явного утверждения; коммиты — по явной команде;
   тег `audit/<дата>` на аудит-коммит (по методике).
4. Артефакты рендера: `/tmp/opencode/ux_audit/` (в репо не коммитятся; в отчёт —
   ссылки/инлайны по согласованию).
