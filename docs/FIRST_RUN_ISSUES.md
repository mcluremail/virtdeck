## #1 — диалог «Добавить сервер»: порт по умолчанию и пропажа поля

Статус: ИСПРАВЛЕНО.

Симптомы:
1. По умолчанию «Proxmox VE», в поле Порт — **8007** (для PVE должен быть **8006**; 8007 — это PBS).
2. Переключение на PBS: порт остаётся 8007 (совпадение, а не логика).
3. Переключение обратно на PVE: **поле Порт исчезает**.

Причина (`virtdeck/ui/add_server_dialog.py`):
- `:91` `self.port_input = QLineEdit("8007")` — жёсткий дефолт 8007 вместо 8006;
- `:232-234` `_on_type_changed()`: `self.port_input.setVisible(pbs)` — поле
  скрывается целиком для PVE, значение не переключается. При старте диалога
  `_on_type_changed` не вызывается, поэтому виден исходный 8007.

План фикса: дефолт 8006; в `_on_type_changed` поле всегда видно, значение
свапается 8006↔8007 (если пользователь не ввёл своё); метка порта — обычная
(не pve-only); вызвать `_on_type_changed()` после построения формы. Тесты на
`tests/ui/test_add_server_dialog.py`.

## #2 — кнопка «Показать» (токен): текст не влезает в русской локали

Статус: ИСПРАВЛЕНО.

Симптом: в русской локали надпись «Показать» обрезается на кнопке
показа значения токена (диалог «Добавить сервер», секция Token).

Причина: `virtdeck/ui/add_server_dialog.py:158` —
`self._token_show_btn.setFixedWidth(60)` — ширина подобрана под английские
"Show"/"Hide"; русское «Показать» (и др. локали) не помещается.

План фикса: убрать `setFixedWidth`, дать кнопке размер по содержимому
(`sizeHint`/adjustSize при смене текста) либо `setMinimumWidth(60)`;
проверить обе подписи «Показать»/«Скрыть» и en/ru локали.

## #3 — кластер не распознаётся без ручной галочки «cluster representative»

Статус: ИСПРАВЛЕНО (автоопределение кластера; галочка удалена по решению
владельца).

Симптом: добавил `pve01.ros.linru.grp` без галочки «This is a cluster
representative» → добавился один хост; токен создался на pve01 (прописан в
конфиге этого хоста), но в кластере его не видно. Необходимость галочки
неочевидна.

Причина: кластерность включается только вручную (`cluster_rep_cb`,
`add_server_dialog.py:193`; конфиг `cluster_rep: true` :372-374). Автоопределения нет.

Ответ на вопрос владельца: **да, можем**. После «Get token» мы уже авторизованы
на ноде — `GET /cluster/status` (`provider/_cluster.py:24`) на любом участнике
кластера возвращает список нод и имя кластера (в standalone — одну ноду,
quorate). План:
1. После создания токена автоматически запросить cluster/status.
2. Нод > 1 → отметить `cluster_rep_cb`, подставить имя кластера из ответа
   (запись `type: "cluster"`), показать в статусе «Обнаружен кластер
   <name>: N нод».
3. Одна нода → standalone, галочка снята, статус «Standalone host».
4. Переформулировать подпись галочки (например, «Добавить все ноды кластера»)
   + tooltip; галочка остаётся ручным override.
Замечание: токен root@pam живёт только на ноде создания (realm per-node) —
это норма PVE; запросы к кластеру идут через представителя, токен на нём
уже есть. В UI стоит показать, где лежит токен (нода создания).

### Решение по #3 (обсуждение с владельцем, 2026-09-15)

Галочка «This is a cluster representative» — **убрать**, автоопределение
полностью заменяет её:
- нода в кластере → cluster/status (имя + ноды) → добавляется кластер целиком;
- standalone → одиночный хост;
- API не ответил → fallback: одиночный хост (как сейчас).
Вместо галочки — информационная строка в диалоге («Обнаружен кластер X:
N нод» / «Standalone host»), поле Cluster авто-заполняется, остаётся
редактируемым. Сценарий «только одна нода из кластера» покрывается
добавлением кластера + удалением лишних нод в дереве.

## #4 — «движок тем не работает: не увидел новых иконок» — ИСПРАВЛЕНО

Статус: ИСПРАВЛЕНО.

Симптом: владелец переключил тему (Breeze) и не увидел новых иконок;
тёмные темы казались наполовину светлыми.

Диагноз (воспроизведением, offscreen-скриншоты): сам движок тем работает —
токены/QSS/плотность применяются. Два реальных дефекта:
1. **Иконки тулбара не обновлялись при смене темы**: `QAction` создавались с
   `get_icon(...)` один раз при построении тулбара; `init_icons()` в
   `_on_theme_applied` пересобирает кэш иконок, но кнопки держат ссылки на
   старые `QIcon` → светлая (тёмная обводка) иконка на тёмном тулбаре,
   почти невидима. То же для кнопок действий панели деталей и вкладок
   (`addTab` иконки).
2. **«Голые» QWidget-контейнеры не красились QSS** (центральная панель
   «Select object in tree», фон под прозрачной шапкой таблицы задач) —
   сквозь них светилась системная светлая палитра → тёмные темы выглядели
   сломанными пополам.

Фикс:
- `theme.py::_build_qss` — базовое правило `QWidget { background: {BG} }`
  (частные правила перекрывают его: QToolBar/QTreeWidget/QToolButton и пр.);
- `mainwindow.py` — `self._toolbar_icon_actions` (список пар
  action→имя иконки), в `_on_theme_applied` иконки переприсваиваются
  после `init_icons()`; вызов `detail_panel.reapply_theme()`;
- `detail_panel/__init__.py` — `reapply_theme()`: иконки кнопок действий
  (`_action_buttons`, `_extra_action_buttons`), консольной кнопки и вкладок
  (`_tab_icon_keys` заполняется в `_add_next_tab`).

Оговорка: Breeze-плагин перекрывает только 8 иконок (vm, host, cluster,
pool, storage, backup, refresh, search) — остальные ~30 рисуются встроенным
набором, перекрашенным токенами темы (ICON_FG). Это осознанный дизайн
(частичный override по контракту ThemePlugin), не баг.
