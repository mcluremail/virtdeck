## 🔴 Найдено и исправлено

### E1. Палитра предлагала host-действия на скелетоне первичной загрузки
Скелетон (`start_loading`) создаёт placeholder-элементы с укороченным
ключом `("host", имя)` — без `node`/`host_name`. Контекст-меню на таком
элементе не строится (`host_name` не резолвится → меню без действий), а
новая палитра M2 получала от `selection_for_item()` Selection с
`kind="host"` и пустым `host_name` — и предлагала Create VM / Delete host
/ Refresh token / Create cluster… без enabled-предикатов. Invoke «Delete
host» эмитил `host_remove_requested("host", "")`: для кластера пустое имя
отсекается в `_on_host_remove`, для хоста — нет → диалог подтверждения с
пустым именем (потери данных нет — `matched` пуст, но UX сломан).
Исправлено: `selection_for_item()` возвращает пустой Selection для
host-ключа, по которому `host_name` не резолвится — паритет с меню.
Регресс: `test_skeleton_host_key_yields_empty_selection`
(tests/ui/test_tree_panel.py::TestCurrentSelection).

### E2 (minor). Палитра не обновляла размер иконок при смене темы
`retheme()` палитры перестилизовал цвета, но `setIconSize` списка
фиксировался при создании: палитра, созданная в теме с base 16px, после
переключения на Breeze (24px) рисовала иконки уменьшенными. Исправлено:
`retheme()` обновляет `_list.setIconSize(QSize(base_size(), base_size()))`.
Регресс: `test_retheme_updates_icon_size` (tests/ui/test_command_palette.py).

## 🟡 Наблюдения (приняты как есть)

### W1. Одно-нодовый кластер больше нельзя пометить представителем вручную
Автодетект ставит `cluster_rep=True` только при `nodes > 1`; чекбокс
«cluster representative» удалён (668e4d7). Для вырожденного случая
«кластер из одной ноды» (`/cluster/status` отдаёт type=cluster + 1 ноду)
хост добавится как standalone с текстовой меткой кластера. Осознанное
упрощение zero-start-прохода; если понадобится — верни выбор в диалог
при обнаруженном кластере.

### W2. Палитра показывает два delete для ВМ
Для выделенной ВМ в палитре соседствуют `object.delete` («Delete», Del)
и `vm.delete` («Delete VM») — разный invoke (`request_delete_current`
маршрутизует по типу). Дубль не вреден, но можно скрывать родовой
delete при наличии типового (follow-up M2).

### W3. Двойное чтение `load_ui_state("theme")` в `_build_theme_switcher`
`saved` читается до restore-загрузки и ещё раз при заполнении комбобокса.
Косметика, поведение корректно.

### W4. Реверс-лукап токена в MetricCard неоднозначен при равных hex
`_token_for()` возвращает первое имя токена с таким значением; в светлой
теме `TEXT_DIM == DISABLED` (#868a8f). Значения сходятся при retheme,
расхождение — только в имени токена. Приемлемо; для строгости можно
передавать имя токена явно.

### W5. Legacy-запись keyring не удаляется после успешной миграции
`_load_token` перезаписывает токен под `virtdeck`, но запись `pvecenter`
оставляет — намеренно (fallback при неудаче перезаписи/даунгрейде);
очистка обеих записей происходит в `_delete_token`. Если захочется
ретайрить — удалять legacy после успешного `set_password`.
